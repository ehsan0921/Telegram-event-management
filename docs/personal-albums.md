# Personal albums and photo likes

Personal albums reuse photo collections, Telegram upload and existing sharing controls. New personal albums start private; older collections keep their settings and links. Upload original files using Add files in Telegram. The Mini App can link selected original media from accessible galleries and remove items from owned photo albums after confirmation.

An imported item stores a reference, never a second file ID or a copy. View permission does not grant republishing permission: other users need the source owner's explicit linking consent (legacy default off). Every destination viewer and its owner must retain current source access. Source link rotation, per-user media revocation, disabled sharing and withdrawn named invitations are checked again for metadata, previews, likes, sends, status requests and queued delivery. Reference chains are rejected. An owner cannot use a personal album to widen a source audience. Linked items may therefore be unavailable to recipients who lack source access.

Foreign references bind to the source access and linking-policy versions. Turning consent off and back on does not revive them. Remove an unavailable link and explicitly link the original again after renewed consent. Removing a reference does not remove source media, receipts or uncertain delivery evidence. Previously delivered/in-flight copies cannot be recalled.

Photo likes use authenticated user identity and canonical original identity; setting liked=true/false is idempotent. Counts and the current user’s liked state are available only to current authorized photo viewers. The Mini App does not show a liker list; the API returns no other users’ names, identities or pagination. Existing like records remain intact. Owner-only access controls identify exact users, require confirmation and compare versions. Media-only blocks preserve event RSVPs, payments and other event features. Existing standalone sharing controls rotate old capability links. Event invitation tokens retain their existing invitation semantics.

No schema migration is required. Compatible event fields and media_likes/media_import business records use the existing records table. Import request tombstones survive removals and database snapshots. Never clear these records to retry a request. The tested feature rollback is ALBUM_SOCIAL_ENABLED=false on this privacy-aware Worker: it pauses new social writes and hides social controls while retaining reference authorization, revocation and all records. Keep existing variables/secrets when setting it. Do not restore/reset D1 or deploy pre-feature code after new access blocks/references exist; older code does not enforce these access rules. Use this safe mode and a forward fix instead.

Validation uses fictional SQLite/D1 fixtures, signed Mini App requests and mocked Telegram. It covers revocation, stale links, source consent epochs, current source/destination access, uncertain receipts, native batching, count-only like privacy, idempotence, and UI confirmation/state. These checks do not establish physical iOS/Android or real Telegram client behavior.
